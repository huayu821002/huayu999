# 2026-10-24

## 1688 采集器：价格误采集根因定位与修复（commit ae35b74，已部署）

### 背景
崔元峰回传 1688 商品 1053022605528（欧美网纱头饰…，义乌市流雅饰品）的采集诊断：
采出 priceMin=priceMax=wholesalePrice=11，`priceWhy = sku:first(offerList → …)`，
skuPrices 里 5 条全是**别的商品**（亚马逊爆款套装 ¥16.5、欧根纱发箍 ¥12…）。

### 根因（三个叠加）
1. **推荐位被当成 SKU 列表**
   `offerList` / `majorRecommendOfferInfos` / `relationRecommendOfferInfos` / `itemList`
   都是「同店其它商品 / 相似推荐」列表，条目字段是 `offerUrl / offerId / behaviorTag / isCurrentOffer / title`，
   是**商品卡片**不是规格行。旧 `collectSkuEntries()` 只靠「key 名像 sku」或「有 priceText」判定 → 误判。
2. **重放请求污染采集结果**
   诊断里多个 `mtop.1688.mmga.offerdetail.service` 返回 `invalid param` / `{}`：
   1688 的 mtop 接口把 `data` 参数放在 query 尾部，旧的 `replayResources()` 从 performance 拿到的 URL 被
   **截断到 300 字符** → 丢了 `data=` → GET 重放必然 invalid param；
   更糟的是重放走的是被 hook 过的 `window.fetch`，这些垃圾响应又被**当成页面数据存进 STORE**。
   于是真实详情报文始终没拿到，只能落到推荐位价格。
3. **规格名取整段商品标题** → firstSku 变成「欧美网纱头饰羽毛头花欧根纱礼帽头饰赛马会复古走秀花朵发夹发饰」。

### 修复（core 3.2.0 → 3.3.0，采集脚本 2.10.0 → 2.11.0）
- `NOISE_KEY_RE` + `isCardItem()`：推荐容器路径与商品卡片条目一律排除出价格/SKU 提取。
- `collectSkuEntries()` 收紧：必须有真规格字段；`skuSpecOfItem()` 不用超长标题当规格名。
- 新增 `pickCurrentOfferCard()`：无真 SKU 时取 `isCurrentOffer===true` 或 `offerId` 匹配的当前商品价。
- `replayResources()` 改用未挂钩的原始 fetch（`window.__FF1688_ORIG_FETCH__`），URL 不再截断；
  新增 `isUselessPayload()` 过滤 `success:false` / `reason:invalid param` / `data:{}`。
- 新增 `pushRequest()` 记录 mtop 请求的 method+body → `replayCapturedRequests()` 原样 POST 重放。
- 新增 `scanInlineData()`：扫 `__INIT_DATA__` / `__NEXT_DATA__` 等 window 全局 + 内联 script 找首屏详情 JSON。
- `parseLoose()`：兼容 JSONP 包装。
- DOM 兜底：排除推荐卡片价格，支持 `¥9` 单值。
- 诊断新增 `sources` / `apiList` / `payloadTopKeys` / `skuLikePaths`（直接定位真实 SKU 在哪个报文）。
